# Личный сайт Артёма Коваленко

## Публикация статьи из My Zettel

1. Пишите исходную статью в My Zettel в Markdown (`.md`).
2. Скопируйте готовый текст в `_publications/unique-article-slug.md` этого репозитория. Образец заголовка файла — `templates/article.md`.
3. Заполните `title`, `description`, `date`, `lang` и `permalink`. Текст начинается после второго `---`. Языки статьи: `ru` или `en`; автоматического перевода текста нет.
4. Используйте обычные Markdown-ссылки вместо Obsidian `[[ссылок]]` и `![[вложений]]`. Картинки скопируйте в `assets/articles/unique-article-slug/` и вставьте как `![Описание](/assets/articles/unique-article-slug/image.jpg)`. Проверьте, что в экспорт не попали личные заметки.
5. Отправьте изменения в GitHub. В настройках GitHub Pages должен быть выбран режим **Deploy from a branch** и корень репозитория соответствующей ветки: Jekyll преобразует Markdown в HTML при публикации. Локальное сохранение файла само по себе сайт не обновляет.

Каталог статей: `/publications/`, с поиском по заголовку и описанию. Статьи автоматически добавляются в него по дате.

## Постоянные ссылки

Адрес задаёт `permalink`, например `/publications/unique-article-slug/`. После публикации его не меняйте и не используйте для другой статьи. Заголовок, оформление и имя Markdown-файла можно менять, сохраняя `permalink`. При переработке сайта сохраняйте обслуживание всех опубликованных адресов. Смена домена требует сохранения старого домена и перенаправлений; сам по себе permalink этого не обеспечивает.

Общее оформление статей: `_layouts/publication.html` и `assets/publications.css`. Шаблон в `templates/` не публикуется. Для черновиков храните тексты в My Zettel до готовности.

## Выгрузка по запросу из My Zettel (итерация 3)

Рабочие оригиналы находятся в `MyZettel/branding/sites/artemkovalenko1991/publications/<папка статьи>/`. Текст, ТЗ на иллюстрации и изображения можно хранить рядом. Выгружаем только выбранную статью и картинки, вставленные в её текст; ТЗ и прочие заметки не копируем. Это односторонняя выгрузка по запросу, без фоновой синхронизации и удаления файлов.

Когда статья готова, попросите: «Выгрузи статью из <полный путь> на сайт». Для новой публикации нужны постоянный slug, краткое описание, дата и язык. Если они не заданы, уточняем перед выгрузкой. Для уже опубликованной статьи сохраняем существующий permalink.

Помощник первой выгрузки — `scripts/export_article.py` (Python 3.9+). Пример запуска из корня репозитория:

```sh
python3 scripts/export_article.py '/полный/путь/к/статье.md' --slug project-discovery --description 'Описание для каталога' --date 2026-11-12
```

Сначала команда только показывает план. Добавление `--write` записывает Markdown в `_publications/<slug>.md`, а используемые локальные изображения — в `assets/articles/<slug>/` с заменой ссылок. Поддерживаются обычные Markdown-вставки без пробелов в пути (пробелы кодируйте `%20`) и Obsidian `![[image.png]]`. Изображения должны находиться внутри папки статьи. Отсутствующие картинки останавливают экспорт; статья без картинок допустима. Исходники с YAML-свойствами требуют отдельного согласования реквизитов. Обновления существующих публикаций выполняем отдельно, сохраняя адрес.

После выгрузки проверяем текст, ссылки и список изменений. Только затем отдельным шагом создаём коммит и отправляем относящиеся к публикации файлы в GitHub. Скрипт сам не делает commit/push. При запросе «выгрузи и опубликуй» выполняем и этот шаг; посторонние изменения Obsidian не включаем.
